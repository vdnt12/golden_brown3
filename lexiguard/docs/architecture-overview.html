1Layers and trust boundaries

Everything runs in one process tree on one machine. The browser talks to FastAPI over loopback; FastAPI talks to Ollama over loopback; document data stays in per-document SQLite files. The model is the only component that proposes text — it never authors quotes, pages or statuses.

Browser — React + Vite + TypeScript builds

Launch link carries a one-time code in the URL fragment → exchanged for a memory-only bearer token. No storage APIs, no CDN, no inline script/style. Shows quotes, citations and statuses only.

2Ask lifecycle — one question, end to end

The state machine is fixed: RECEIVE → CLASSIFY → PLAN → RETRIEVE → ANALYZE → VALIDATE → RESPOND. The fast path makes one model call; refinement adds at most one more; the hard ceiling is four calls per question.

  1. Receive and classify

    backendValidate the question (≤500 chars), bind it to a document bound server-side, run the deterministic pre-router (fact / term / coverage / scope / legal boundary). A model route proposal is used only when the pre-router is unsure; the stricter route wins.

  2. Plan and retrieve

    backendBuild a quoted FTS5 query, expand with the rental-topic lexicon and extracted cross-references, cap at 12 chunks, score by BM25. The silence gate decides whether a “not found” claim is even permissible.

  3. Analyse with the local model

    gemma 4Reads a nonce-delimited, bounded evidence packet and returns {points:[{point_id, kind, text, sids}]}. It may only cite ids present in this run’s packet. No tools, no quotes, no verdicts.

  4. Validate deterministically

    backendSchema → provenance → quote integrity → literals & dates → modality/negation → tenant/landlord roles → conflict section diversity → legal-verdict scanner. A point that fails is dropped, never softened.

  5. Render the answer

    backendAttach the exact stored quotes, page and section. Separate explicit points from interpretations, concerns and ambiguities. If nothing survives validation, degrade to INSUFFICIENT_EVIDENCE.

  6. Respond with a truthful status

    backendResolve status by fixed precedence, attach missing-information reasons and (only if already in the store) escalation questions. legal_verdict is always null.

Budgets that never bend
  • 1 fast-path model call; +1 refinement; ceiling 4 including retries
  • ≤8 tool calls, ≤2 retrieval loops, ≤12 evidence chunks
  • Packet ≈2,500 estimated tokens (chars ÷ 3.2), pre-budgeted against num_ctx 8192
  • Wall clock ≤ 4× Day-0 p50; skip refinement once half the budget is spent
  • Question ≤500 characters; one format retry, then fail closed
Who decides what
  • Model: route proposal (only if asked), query expansion, one NextAction, wording of restatement/interpretation/concern points
  • Backend: ids, offsets, retrieval, citations, pages, sections, statuses, missing-information codes, legal policy, deletion, network policy
  • Never: model-authored quotes, file paths, evidence ids or legal conclusions

3Trust boundaries

The trust boundary is the request-handling code, not the loopback interface. Same-user malware, OS compromise and physical access are explicitly out of scope.

ZoneContainsRule
UntrustedUploaded file, extracted text, OCR output, headers/footnotes/tables/metadata, filenames, model answers, router proposals, tool arguments Never concatenated into instructions as authoritative; bounded, nonce-delimited, validated; the model cannot cause a network call, file access or deletion.
TrustedFastAPI handlers, validator, renderer, legal policy, store layer, deletion coordinator Owns quotes, ids, statuses, paths and policy. Re-derives everything shown to the user from stored data.
Semi-trustedPDF parser child process, OCR executable, local model runtime Sandboxed by limits/timeouts; output re-validated by the parent; failures fail closed.
Out of scopeSame-user malware, root/admin, disk forensics, cloud-synced folders Documented in PRIVACY.md and LIMITATIONS.md; never contradicted by UI wording.

4Data model

One SQLite database per document. Sentences are the citation unit; chunks are the retrieval unit; FTS5 is an external-content index with triggers, so lexical search never diverges from stored text.

documentsdoc_id (32-hex) · sha256 · display name · pages · language · created_at
→
pagespage_no · method (text/ocr) · text · hashes · quality flags
→
sentencessid · page · char start/end · section · text
→
chunkschunk_id · sid range · text · page · section
→
chunks_ftsFTS5 external content · BM25 · number index
Invariants
  • sid is stable for a document version and maps to exact stored bytes
  • Quotes are sliced from sentences.text, never from the model
  • secure_delete=ON, journal_mode=DELETE, foreign keys on, no WAL, no history
  • Run ledger stores route, tool names, counts, validation codes and duration — never text
Retention
  • Source + DB: until the user deletes the document
  • Question and answer: request lifetime only
  • Browser token: JS memory; tab lifetime
  • Deletion: directory removed, canary scan, honest “not forensic erasure” report
